# Clipboard do sistema — implementação e gate pendente

18/10/2026. Complemento dos lotes 2/3; não constitui aprovação da integração nativa nem full review.

O editor usa a API assíncrona do Electron 44.8.0, com publicação atômica do formato editável EdiPDF e texto simples. Uma única anotação de imagem também publica PNG. Não há cache interno usado como alternativa quando o sistema contém outro conteúdo. Colar prioriza o formato EdiPDF, depois PNG e texto; um envelope EdiPDF inválido é recusado, sem fallback silencioso. MIME types são fixos; HTML, arquivos, links e comandos não são executados. Referência primária: [ClipboardItem](https://www.electronjs.org/docs/latest/api/clipboard-item).

Main/preload expõem somente copiar anotações e colar conteúdo do perfil, sob os gates/origem do SDK. Operações de clipboard são serializadas. Limites antes de schema/serialização: 16 MB, mil anotações e cem mil elementos; textos externos têm até cem mil caracteres. O leitor verifica o tamanho do Blob antes da cópia para IPC. A API nativa pode materializar os dados antes disso: não se declara limite de memória do sistema operacional. Imagens têm validação de formato/resolução antes do decoder do editor. Copiar seleção inválida não alcança a escrita do OS.

A colagem regenerará IDs/grupos e conservará a origem. Texto abre uma caixa com prévia/validação de composição antes de aplicar. Imagens usam a inserção existente, agora com conferência de revisão/página após a leitura assíncrona. Documento fechado, trocado ou alterado não recebe o resultado de uma leitura antiga. PDFs restritos conservam as regras de cópia/edição da interface.

Quatro testes específicos passaram: Unicode e colagem entre documentos, grupos/identidades/imutabilidade; versões futuras, IDs repetidos, UTF-8 inválido, excesso de tamanho e URLs de imagem; texto literal/quebras/nulos; orçamento de grafos, ciclos e dados compartilhados. **246 testes do app aprovados**, tipos do app e harness e Biome dos arquivos novos aprovados. Evidências: `.cache/edipdf-analysis/test-clipboard-all.txt`, `typecheck-clipboard.txt`, `types-clipboard-harness.txt`, `biome-clipboard.txt`. Regressão Electron completa aprovada em `.cache/edipdf-analysis/native-clipboard-regression.txt`, com build normal restaurado em `build-clipboard-normal.txt`, sem usar o clipboard pessoal; o gate de cópia recebe dados inválidos que impedem escrita mesmo se o gate regredir.

O harness `pnpm --filter @informach/edipdf exec node scripts/test-clipboard.mts` prepara uma estação Windows exclusiva e não interativa, cria um desktop privado e exige que o Electron confira o nome da estação antes de qualquer acesso ao clipboard. As estações têm clipboards distintos, conforme a [documentação do Windows](https://learn.microsoft.com/en-us/windows/win32/winstation/window-stations). Nunca reutiliza uma estação existente, troca o desktop visível nem captura/restaura o conteúdo do usuário. Fecha somente handles/processo que criou. A estação com nome exclusivo exige ambiente de teste privilegiado: esta sessão recebeu erro 5, antes de qualquer acesso ao clipboard. A alternativa sem nome retornou 183/existente e foi recusada; o harness manteve o requisito de isolamento, sem enfraquecer o gate. Evidência da tentativa: `.cache/edipdf-analysis/native-clipboard.txt`.

Gate ainda obrigatório: executar o harness em ambiente Windows isolado com a permissão necessária; conferir formatos nativos, leitura/escrita, Unicode, PNG/pixels, preservação em falhas e prioridades. Também falta jornada de UI copiar/colar entre documentos e programas, desfazer, texto revisado e revisões obsoletas. A implementação não será registrada como integração nativa homologada enquanto esses gates não passarem. Não há necessidade de serviço externo. O bloqueio desse teste não impede trabalhar nos demais complementos.
